## 1. 제품 목표

사용자가 한국어로 작업을 요청하면 에이전트가 내용을 듣고 `llm.example.test` 작업 처리 결과를 한국어 음성으로 답한다. 같은 에이전트를 웹에서 사용하고, 필요할 때 에이전트가 Grandstream HT813의 FXO에 연결된 외부 전화선으로 발신할 수 있어야 한다. 외부 회선으로 걸려 오는 모든 통화도 에이전트가 받아 한국어 음성 대화를 제공한다. FXS 전화기는 연결 후 외부 발신에 사용할 수 있어야 한다.

현재 Asterisk 서버는 없으며 초기 제품은 이를 설치 조건으로 요구하지 않는다. 현재 작업 어댑터는 외부 chat completion API의 응답 텍스트를 받는다. 예약·주문·외부 시스템 변경을 수행하는 도구 실행 기능의 성공을 이 제품 기준으로 주장하지 않는다. HT813·FXS의 현장 연결과 운영 상태는 실행 직전 다시 확인한다.

첫 서비스 개시는 **전화 착신·정확한 허용 번호 발신·착신 목록과 발착신 대화 조회**를 대상으로 한다. 웹 사용자 음성 화면과 FXS 독립 발신은 요구를 유지하되 후속 범위로 둔다. 이 문서의 요구 버전과 두 앱의 패키지 버전은 `0.1.0`이며, `dev/v0.0.1`은 기존 Git 개발 브랜치 이름이다. 실제 배포 버전·이미지·모델 revision은 M11 릴리스 명세로 고정한다. [기준과 증거](../../guides/service-readiness-baseline.md), [운영 계약](../../guides/service-readiness-contract.md)을 함께 읽는다.

## 2. 대상 사용자와 초기 범위

- 웹 사용자는 브라우저에서 음성 요청을 시작하고, 작업 결과를 텍스트와 음성으로 확인한다.
- 에이전트 운영자는 허용한 번호로만 FXO 회선을 통해 외부 발신한다. 발신 번호, 실패 상태, 통화 종료 상태를 확인할 수 있어야 한다.
- 외부 발신자는 발신자 번호와 관계없이 FXO 회선으로 전화해 에이전트와 대화한다. 발신자 번호를 에이전트 접근 허용 목록으로 사용하지 않는다.
- FXS 전화기 사용자는 전화기가 연결된 뒤 전화기에서 누른 번호로 외부 회선에 발신한다. FXS 실장 검증은 전화기 연결 전 보류한다.
- 초기 활성 세션은 웹과 에이전트 전화 세션을 합쳐 1개다. 회선 사용 중이거나 세션이 이미 있으면 새 요청에 이유를 알려야 한다.

## 3. 사용자 요구사항

### PRD-01. 웹 한국어 음성 작업

사용자는 웹에서 음성 요청을 시작·중단할 수 있어야 한다. 에이전트는 인식한 최종 요청과 작업 결과를 보여 주고, 한국어 음성으로 답해야 한다. 마이크 권한 거부, 음성 인식 실패, 작업 처리 지연, 음성 합성 실패가 발생하면 해당 단계의 실패를 알리고 세션을 정리한다.

### PRD-02. 에이전트의 외부 발신

에이전트는 운영자가 허용한 번호에만 HT813 FXO 회선을 사용해 발신할 수 있어야 한다. 발신 요청에는 번호를 명시하고, 연결 시도·벨 울림·통화 중·통화 종료 또는 실패 상태를 구분해 보여 준다. 허용되지 않은 번호와 전화 기능 코드는 통화가 시작되기 전에 거부한다. 외부 회선이 이미 사용 중이면 중복 발신하지 않고 점유 상태를 알린다.

상대 사용자가 전화를 받으면 같은 통화 안에서 여러 번 질의하고 에이전트의 음성 답변을 들으며 대화를 계속할 수 있어야 한다. 에이전트는 각 답변 뒤 전화를 자동으로 끊지 않는다. 정상 통화는 상대 사용자가 전화기에서 통화 종료를 누를 때 끝난다. 질의 한 번의 종료는 통화 종료가 아니다. 후속 질문은 같은 통화의 앞선 질의·답변을 이해할 수 있어야 한다. 이전 통화 내용은 새 통화의 문맥으로 자동 이어지지 않는다.

### PRD-03. 모든 외부 착신의 에이전트 연결

HT813 FXO 외부 회선으로 들어오는 통화는 발신자 번호의 허용 목록 없이 모두 에이전트로 연결되어야 한다. 발신자 번호가 표시되지 않아도 번호만을 이유로 에이전트 접근을 거부하지 않는다. 사용자는 같은 통화에서 여러 번 질의하고 음성 답변을 들을 수 있으며, 정상 통화는 전화를 건 사용자가 종료할 때 끝난다. 이미 웹 또는 전화 세션이 사용 중이면 새 통화를 중복 처리하지 않고 통화 불가 상태로 응답한다. 이 착신 경로는 이전의 외부 착신→FXS 전달 요구를 대체한다. M6에서 일부 실착신 대화 성공을 확인했으나, 개시 후보의 반복·종료 지연·충돌·조회 결과는 M10의 별도 승인된 실장 시험으로 확인한다.

### PRD-04. FXS 전화기의 외부 발신

FXS 전화기에서 누른 일반 전화번호는 가능하다면 외부 전화선으로 발신되어야 한다. 에이전트를 호출하기 위한 별도 번호나 복잡한 IP 발신 코드를 사용자에게 요구하지 않는다. FXO와 FXS가 같은 회선을 사용하는 중에는 충돌을 피하고 현재 이용할 수 없음을 전화기에서 확인할 수 있어야 한다. 실제 번호 해석과 회선 점유 동작은 전화기 연결 뒤 검증한다.

### PRD-05. 응답 음성의 사용감

한국어 TTS가 알아듣기 쉬워야 한다. 사용자 청취 피드백에서는 MeloTTS의 음질은 좋지만 기본 발화 속도는 느렸다. 1.15배도 느리다는 의견에 따라 1.25배와 1.5배 샘플을 비교했고, 사용자가 **초기 발화 속도 1.25배**를 선택했다. 실제 전화 음성에서 필요하면 속도를 조정할 수 있어야 한다. 합성 처리 지연과 실제 말하는 속도는 별도로 평가한다.

### PRD-06. 보안·보존·장애 대응

API 키와 장비 인증 비밀은 화면·로그·저장소에 노출하지 않는다. 녹취와 원문 데이터는 생성 시점부터 30일 보존한 뒤 삭제한다. 사용자는 취소·시간 초과·외부 서비스 장애 시 실패 상태를 볼 수 있고 세션 및 전화 회선이 정리되어 다시 시도할 수 있어야 한다.

### PRD-07. AI 착신내역 조회

운영자는 AI가 받은 외부 전화의 통화 ID, 시작·종료 시각, 상태 및 HT813가 전달한 **발신자 번호 전체**를 최신순으로 조회할 수 있어야 한다. 번호가 제공되지 않거나 인식할 수 없으면 번호 없음으로 구분한다. 번호는 장비가 제공한 표시 정보이며 신원 인증을 뜻하지 않는다. 이력 조회는 인증된 운영 경계에만 허용하고 기록은 기존 보존 정책에 따라 생성 후 30일에 삭제한다. 조회 기능 도입 전 통화의 발신자 번호를 소급 생성하지 않으며, 백엔드가 중지된 동안의 부재중 전화까지 조회한다고 표시하지 않는다.

### PRD-08. 통화별 대화내역 조회

운영자는 통화 ID를 지정해 보존 중인 사용자 최종 전사와 AI 최종 응답을 원래 턴 순서대로 조회할 수 있어야 한다. 외부 착신과 AI 발신에 같은 형식을 적용한다. 응답이 생성되지 않은 턴은 존재하는 사용자 발화만 보여주고, 무음 통화나 30일 만료 뒤에는 존재하지 않는 대화를 만들어 내지 않는다. 대화 원문은 인증된 로컬 운영 API로만 제공하며 일반 로그·파일명·오류 메시지에는 쓰지 않는다. 녹취·부분 전사·다른 통화의 내용은 포함하지 않는다.

### PRD-09. 전화 우선 운영과 복구

운영 담당자는 **김화균**이다. 에이전트는 매 실전화 발신 직전에 김화균 사용자에게 먼저 요청하고, 사용자의 응답을 통해 해당 발신 진행이 확인될 때까지 발신하지 않는다. 이는 실행 묶음의 Gate 2 승인과 별개 조건이며, 과거 승인·MR 병합·시간 경과만으로 개별 발신을 승인받았다고 간주하지 않는다. 실제 번호·비밀은 추적되지 않는 운영 설정에서 관리한다.

운영자는 로컬 인증 API 또는 인증된 SSH 터널을 통해 발신·취소·착신 목록·대화를 조회한다. 서비스 운영 시간과 장애 연락 경로는 아직 미정이며, 후속 실행안에서 확정해야 한다. 사용자는 동시 1세션, 장애 시 이용 불가, 백엔드 중지 중 부재중 기록 미지원, Caller ID의 표시 정보 한계를 안내받아야 한다.

상시 운영은 재부팅 뒤 같은 보존 키와 기존 기록을 복구하고, 모델·백엔드 준비 및 장애 알림을 확인한 후 판정한다. 키나 데이터 삭제를 복구 수단으로 사용하지 않고 FXS 자동 우회를 가정하지 않는다. 키 저장·복구 B안과 품질 수용 수치는 M9 MR #3 사용자 병합으로 설계 인수됐다. 실제 구현·시험·운영 개시는 별도다. 수치와 검증 추적은 SRS-O05~O10 및 운영 계약이 소유한다. 제한 운영은 72시간·30통 이상(발착신 각각 10통 이상)·60턴 이상을 수용 목표로 하며 현재 안정성이나 SLA를 뜻하지 않는다.

## 4. 세 가지 전화 흐름의 완료 기준

|흐름|기대하는 사용자 결과|현재 조건|
|---|---|
|에이전트 → FXO → 외부 번호|허용된 번호에만 전화가 걸리고 같은 통화에서 여러 질의·음성 답변을 반복함. 답변 뒤 연결을 유지하고 상대 사용자가 끊으면 종료 상태가 표시됨|실제 벨·연결·상대 종료 1회 과거 증거. 두 턴·DTMF·반복 신뢰성은 M10 미검증|
|외부 회선 → HT813 → 에이전트|발신자 번호와 관계없이 에이전트가 착신하고 같은 통화에서 여러 질의·음성 답변을 반복함. 발신자가 끊으면 통화가 종료됨|과거 2통화 및 두 번째 2턴 성공. 개시 후보의 Caller ID·종료 수치·조회·충돌은 M10 미검증|
|FXS 전화기 → HT813 → 외부 회선|일반 번호를 누르면 외부로 발신됨|첫 개시 후속 범위. 연결 상태 재확인과 별도 실장 승인 필요|

위 표의 과거 결과는 [공개 증거 요약](../../guides/service-readiness-baseline.md)이며 이번 버전의 재검증 결과가 아니다. M6는 부분 완료이고 M7/M8의 두 조회 API 구현·합성 경계 완료는 운영 배포·실전화 조회 완료와 구분한다. 실제 전화 시험은 대상·시간·회선 영향·원복안을 구체화한 실행안 MR의 사전 사용자 병합(Gate 2)과 매 발신 직전 요청 조건을 충족해야 한다.

## 5. 초기 범위에서 제외한 기능

- `FXS 전화기 → 에이전트` 호출과 외부 착신을 발신자 번호에 따라 FXS/에이전트로 분기하는 기능
- 둘 이상의 동시 에이전트 세션, 여러 PSTN 회선, 통화 전환·녹음 관리 UI
- STT/TTS 신규 모델 학습, 별도 Asterisk 서버 운영, 별도 웹 UI 제작

## 6. 남은 확인 사항

- M10: 정확한 허용 번호 발신 두 턴·DTMF·Caller ID·종료 지연·충돌·실제 파일/조회 경계, BUG-003 원인 또는 재현 조건과 잔여 위험
- M11: 대표 전화 품질·전체 지연·GPU/RAM/swap·장기 문맥·30일 용량, 동일 키 복구·재부팅·롤백·장애 알림
- M12: 승인된 운영 시간·범위의 제한 운영과 운영자 인수, 사용자 개시 판정
- 운영 시간·시험 시간대·장애 연락 경로·시험 번호 참조·회선 영향·비밀 보관/복구 담당 접근 범위 확정
- 후속: 실제 웹 마이크 UI와 FXS 독립 발신. 물리 FXS가 운영 회선을 공유하면 개시 전 점유 충돌을 검증하거나 동시 사용을 제한

OPS-008 Gate 1은 승인됐지만 실행 묶음별 Gate 2는 아직 승인되지 않았다. 이전 M6/M7/M8의 승인은 새 운영 시험·배포 승인을 대신하지 않는다.
