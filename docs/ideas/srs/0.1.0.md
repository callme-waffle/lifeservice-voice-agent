## 1. 시스템 경계와 실행 전제

FastAPI 기반 `orchestrator`의 코어가 STT → 작업 처리 → TTS를 제어한다. 웹과 HT813 FXO 발신·착신 채널은 [공통 계약](../../../apps/orchestrator/src/voice_agent/contracts/)으로 변환하며 코어 내부 또는 서로의 구현을 직접 호출하지 않는다. `llm.example.test`은 작업 처리 대상이고 인증 비밀은 런타임에만 주입한다.

공개 문서의 `192.0.2.0/24`, `198.51.100.0/24`, `llm.example.test`는 예시이며 실제 주소·포트·번호·모델 ID는 추적되지 않는 설정을 사용한다. 현재 HT813 직접 SIP/RTP 및 STT/TTS 상주 HTTP 서비스 구성은 ADR-011을 따른다. STT ready→30초 대기→TTS 워밍업 ready→단일 worker 백엔드 순서이며, 모델과 작업 API로 전송하는 원문을 관측 태그·일반 로그에 넣지 않는다. `/health`가 모델 준비를 확인해도 외부 작업 API의 성공을 보장하지 않는다.

M6 일부 실착신·실발신 증거와 M7/M8 조회 구현·합성 경계 완료를 [공개 기준](../../guides/service-readiness-baseline.md)에서 구분한다. 운영 VM·HT813의 현재 상태와 배포 SHA는 이 문서로 확인한 것이 아니다. OPS-008의 첫 개시는 전화·조회에 한정하고 웹 UI·FXS 독립 발신은 후속으로 유지한다. `0.1.0`은 PRD/SRS와 앱 패키지 버전이며 `dev/v0.0.1`은 기존 개발 브랜치명이다. 배포 이미지·모델 revision은 M11에서 별도 고정한다.

OPS-008 Gate 1은 승인됐지만 실행 묶음별 Gate 2는 미승인이다. 명령·시간·전화 수·키/파일 경계·장비 영향·원복안을 담은 실행안 MR을 사용자 병합한 뒤에만 해당 통합 시험을 생성·실행한다. 이전 M6/M7/M8의 승인은 새 운영 시험·배포 승인으로 확대하지 않는다.

|SRS-C05|STT·작업 처리·TTS 단계와 전화 발신에는 양수 제한 시간을 설정하고 시간 초과·취소·실패를 공개 오류와 세션 상태로 전달한다.|제한 시간 0 또는 상한 초과 설정은 거부되고, 각 단계의 실패 후 세션 자원이 해제된다.|

공통 계약, 코어 단계 제한 시간 집행, 오디오 변환 및 웹·전화 채널 연결은 현재 소스에 구현돼 있다. 구현·단위 증거는 실전화 품질이나 상시 복구를 대신하지 않으며, 이번 후보에서 필요한 회귀·운영 검증은 OPS-008에 추적한다.

## 4. HT813 FXO 에이전트 발신 요구사항

|ID|요구사항|검증 기준|
|---|---|---|
|SRS-T01|발신 번호는 3~15자리 숫자와 선택적 선행 `+`로 제한한다. 비어 있지 않은 허용 정책을 통과해야 한다. 코어의 접두사 정책 지원과 별개로 첫 운영의 허용 목록은 정확한 번호만 사용한다. `*`·`#` 기능 코드는 거부한다.|미허용 번호, 형식 오류, 기능 코드에서는 SIP 발신 시도를 생성하지 않는다. 실제 허용 번호 목록은 운영자가 입력해야 한다.|
|SRS-T02|발신 채널은 HT813 FXO로 SIP 연결을 시도하고 dialing, ringing, active, busy, failed, ended를 이벤트로 낸다.|연결·점유·거절·시간 초과·정상 종료가 각각 상태로 구분된다. 답변 송출 뒤에는 SIP 연결을 유지하고 상대 사용자의 통화 종료 신호에서 정상 종료·자원 정리를 확인한다.|
|SRS-T03|연결된 한 통화에서 사용자의 발화를 여러 번 받아 각각 STT→작업 처리→TTS 음성 답변을 보낸다. 8 kHz 전화 음성을 내부 형식으로 변환하고 DTMF 숫자·기호·지속 시간을 보존한다.|같은 SIP 대화·세션 ID로 두 차례 이상 질의·음성 답변이 오가고 각 답변 뒤 통화가 유지된다. 협상된 코덱·RTP 포트·DTMF 전송 방식에서 청취 가능성과 숫자 전달을 확인한다.|
|SRS-T04|FXO 회선 사용 중 또는 다른 에이전트 세션 사용 중에는 새 발신을 거부한다. 통화 취소·상대 종료·네트워크 중단 후에는 채널이 다음 발신을 위해 정리된다.|fake 피어 단위 테스트와 승인된 실장 시험에서 발신 시도부터 상대 종료·정리까지 웹과 전화를 합친 활성 세션이 1개이며 중복 발신이 없다. 청취·작업 처리·합성 중 상대 종료에도 추가 음성 송출 없이 회선이 회수된다.|
|SRS-T05|한 발화의 종료와 SIP 통화 종료를 구분한다. 발화 종료 뒤에도 통화를 유지해 다음 발화를 받을 수 있으며, 정상 통화는 상대 사용자의 종료 신호로 끝난다.|무음 등 발화 경계로 첫 턴을 마친 뒤 같은 통화에서 다음 턴을 처리한다. 답변 후 자동 BYE가 없고 상대 종료 시 ended 상태와 자원 정리가 확인된다.|
|SRS-T06|후속 작업 요청에는 현재 통화의 최종 전사와 이전 최종 전사·에이전트 응답을 대화 순서대로 `llm.example.test/v1/chat/completions`의 `messages`로 보낸다. 이전 통화·부분 전사·음성 원본은 보내지 않는다.|첫 턴은 현재 최종 전사만, 둘째 턴부터는 같은 통화의 승인된 문맥만 전송한다. 문맥은 통화 종료 때 메모리에서 정리되며 다른 통화 요청·일반 로그에 남지 않는다. Bearer 인증과 재시도 0회는 유지한다.|

HT813의 `Not Registered` 표시는 직접 피어링 성공·실패의 단독 판정 기준이 아니다. 발신 SIP/RTP·다중 턴·문맥 구현은 존재하지만, 과거 실제 벨·연결·상대 종료 1회는 발신 음성 두 턴·DTMF·반복 안정성 증거가 아니다. M10에서 F01~F03 및 필요한 D01~D03을 같은 후보에 연결한다. 이전 승인과 현재 실장 상태를 혼동하지 않고 장비 설정·백업·원복·수신 준비를 실행 직전 확인한다.

## 5. HT813 FXO 외부 착신의 에이전트 연결 요구사항

|SRS-I04|웹 또는 다른 전화 통화가 활성 상태면 새 외부 착신을 중복 처리하지 않고 통화 불가 상태로 응답한다. 이때 FXS로 자동 분기하지 않는다.|동시 착신의 SIP 응답과 모델/API 호출 0회, 기존 통화의 연속성 및 종료 뒤 다음 통화 수락을 확인한다.|
|SRS-I05|착신 접근 정책 변경은 외부 발신 번호 허용 정책 SRS-T01을 완화하지 않는다.|미허용 외부 발신 번호는 계속 SIP 발신 패킷 0개이고, 착신에는 Caller ID 허용 목록을 사용하지 않는다.|
|SRS-I06|인증된 로컬 운영자는 `GET /operator/inbound-calls`로 새 AI 착신의 통화 ID, 시작·종료 시각, 상태, HT813가 SIP로 전달한 발신자 번호 전체 또는 `null`을 최신순·제한된 페이지로 조회한다. 번호는 신원 확인 결과가 아니다.|Caller ID 전송 방식(`From`/`P-Asserted-Identity`/`P-Preferred-Identity`)과 번호 없음·계정 ID 오인 방지, 무음 통화, 종료·중단, 정렬·페이지·인증 거부를 검증한다. 번호는 AES-GCM 아티팩트 안에만 있고 파일명·일반 로그·삭제 감사에는 없으며 생성 후 30일에 삭제된다. 기존 기록의 번호와 백엔드 중지 중 부재중 전화는 조회되지 않는다.|

전체 외부 착신→에이전트 정책과 신뢰 HT813 피어 제한은 유지한다. 과거 실착신 2통화·두 번째 2턴·BYE/RTP 해제·FXO Idle 증거가 있으나 정밀 종료시각·Caller ID 변형·충돌·운영 조회는 미검증이다. M7의 I06 구현·합성 경계 완료와 실제 장비 Caller ID/파일/조회 연결 검증을 구분한다. FXS 자동 착신 우회는 제공한다고 가정하지 않는다.

|SRS-F02|FXS 전화기에서 누른 일반 번호는 가능한 경우 FXO 외부 회선으로 발신된다.|전화기 연결 뒤 일반 번호로 외부 연결·양방향 통화·종료가 확인된다. 에이전트 호출 코드는 요구하지 않는다.|
|SRS-F03|FXO와 FXS가 공유하는 외부 회선이 이미 점유되면 중복 연결을 피하고 사용자가 통화 불가 상태를 알 수 있다.|FXS 전화기 연결 후 FXS 발신과 에이전트 발신·착신의 회선 충돌을 실장 시험에서 구분한다.|

SRS-F02~F03의 FXS 물리 경로는 **미검증**이며 FXS 독립 발신은 첫 개시 후속 범위다. 현장 연결 상태를 다시 확인한다. FXS가 운영 회선을 공유하면 개시 전 점유 충돌을 검증하거나 운영 중 동시 사용을 제한한다. 진단용 FXS 발신에도 별도 승인과 발신 직전 요청 조건이 적용되며 FXS→에이전트는 범위 밖이다.

## 9. 미결정 입력과 변경 관리

- 운영 시간·시험 시간대·장애 연락 경로·실제 번호 설정 참조·회선 영향 범위

- 실제 배포 SHA·모델 revision·캐시·GPU RAM/swap 여유와 대표 질문/장기 문맥의 운영 성능
