# M6 잔여 기능·운영 검증 실행서

## 적용 범위와 현재 판정

이 문서는 [VOIC-FEAT-001-plan-02](../records/1_plans/VOIC-FEAT-001-plan-02.md)의 M6-S2-T2 → M6-S3-T1 → M6-S3-T2 순서로 남은 검증을 실행하기 위한 절차다. 기준 요구사항은 [PRD 0.1.0](../ideas/prd/0.1.0.md)과 [SRS 0.1.0](../ideas/srs/0.1.0.md)이다. 첫 실행은 사용자 Gate 2 승인 뒤 P0·F01 통과, F02 실제 발신 미수신으로 실패했고 F03·F04는 수행하지 않았다([TRY9](../../tests/integrations/ht813/logs/M006_S002_T002-TRY9.md), [VOIC-BUG-003](../records/0_issues/VOIC-BUG-003.md)). 후속 실전화·통합 시험은 실행 직전 범위·시간·회선 영향을 다시 확인하고 Gate 2 승인을 받는다.

이미 확인한 범위는 중복해 완료로 판정하지 않는다. [HT813 실착신 기록](../records/2_logs/VOIC-FEAT-001-log-55.md)에서 실제 착신 두 건, 두 번째 통화의 두 답변, HT813가 시작한 `BYE`·서버 `200 OK`·RTP 해제·사용자 확인 FXO `Idle`이 확인됐다. [브라우저 경계](../../tests/integrations/web/logs/M006_S002_T002-TRY3.md)는 Chrome에 합성 PCM을 넣어 텍스트·음성 반환을 확인했다. [보존 파일 경계](../../tests/integrations/retention/logs/M006_S002_T002-TRY1.md)는 격리된 파일에서 암호화와 정확한 30일 만료를 확인했다. 실제 FXO 발신, 실전화 DTMF, 현장 중복 세션, 종료 지연의 정량 측정, 연속 부하와 운영 재시작은 아직 확인하지 않았다.

**첫 실행 묶음은 P0·F01~F04만** 대상으로 최대 30분 자동 종료가 있는 일시 백엔드를 사용했다. F02 실패 뒤 통화·백엔드·키를 조기 정리했고 같은 승인 범위에서 재발신하지 않았다. F05는 발신원 조건을 충족할 때 별도 승인된 실행에서 수행한다. Q01~Q03은 M6-S2 결과를 검토한 뒤 별도 실행 직전 Gate 2를 받는다. 한 단위가 실패하면 의존하는 다음 단위를 강행하지 않고 상태를 기록한다.

F02 재시험에 앞서 D01→D02→D03 순서로 [발신 미수신 결함](../records/0_issues/VOIC-BUG-003.md)을 진단한다. D01은 장비 화면 읽기만 하며, D02와 D03은 **서로 다른 실제 발신**이므로 각각 사용자가 통화 영향과 수신 준비를 확인한 뒤에만 수행한다. D02가 실패하면 D03을 시작하지 않는다. D03이 성공해야 F02의 다중 턴·종료 요구를 이어서 판정한다. 서버의 SIP `200 OK`나 `active`만으로 외부 휴대전화가 응답했다고 판정하지 않는다.

2026-10-11 [TRY10](../../tests/integrations/ht813/logs/M006_S002_T002-TRY10.md)에서는 사용자 현장 부재로 D02를 건너뛰고, 그 한계를 설명한 뒤 받은 별도 1회 승인으로 D03을 수행했다. 실제 벨 울림·통화 연결·상대 종료와 FXO Idle은 확인했으나, 이 예외는 앞으로의 D02 선행조건이나 새 발신 승인 요건을 변경하지 않는다. 음성 두 턴·DTMF는 사용자가 발화할 수 없어서 미실행이다.

매 실전화 전에 FXO `Idle`, 두 모델 `/ready=200`, 백엔드 `/health=ready`와 `.23:5061/UDP` 수신을 확인한다. 통화 중 의도하지 않은 회선 점유나 SIP/RTP 미해제가 보이면 신규 발신을 중지하고 백엔드의 정상 종료로 `BYE`를 보낸 뒤 HT813의 `Idle` 복귀를 확인한다. 시험 종료 시 백엔드·SIP 관측기·자동 종료 타이머·tmpfs 비밀만 정리하고 기존 암호문 데이터와 보존 키는 유지한다. 키와 전화번호, 전사·답변 본문은 실행 로그에 적지 않는다.

## 테스트 단위별 절차와 합격 기준

### P0. 사전 상태·복구 확인

- **추적:** VOIC-FEAT-001, M6-S2-T1, SRS-I02·O01·O02.
- **Given:** HT813 FXO `Idle`, 종료 톤 감지 `Yes`, 전류 단절·극성 반전 `No`, 시험 대상 회선과 발신 번호가 사용자 소유이고 Git 제외 로컬 `.env`에 정확한 발신 허용 번호가 들어 있다.
- **When:** 작업 VM의 Tempo·Prometheus·Grafana, GPU VM의 전화 NIC `192.0.2.23`, STT/TTS `/ready`, RAM/swap/VRAM, 컨테이너·SIP 포트, 기존 보존 경로와 비밀 **항목 존재 여부만** 확인한다. 장비 설정은 사용자가 Status에서 재확인한다.
- **Then:** 모델 두 개와 관측 스택이 준비되고, FXO는 Idle이며, 백엔드가 아직 중지됐고 5061/4002 포트가 비어 있다. 기존 보존 키를 변경하지 않았고, 30분 자동 종료와 수동 정상 종료 절차가 마련됐어야 한다. 하나라도 다르면 첫 실전화를 시작하지 않는다.
- **증거:** 시각·상태 코드·컨테이너 상태·자원 수치·FXO 사용자 보고. 비밀값과 전체 전화번호 제외.

### F01. 발신 허용 목록의 거부

- **추적:** VOIC-FEAT-001, PRD-02, SRS-T01·I05.
- **Given:** 발신 허용 목록에는 사용자 지정 시험 번호 하나만 있고 SIP 메타데이터 관측기가 켜져 있다.
- **When:** 인증된 loopback 운영 API에 허용되지 않은 **합성 번호**와 기능 코드를 각각 제출한다. 실제 번호로 발신 요청을 보내지 않는다.
- **Then:** 두 요청 모두 통화 시작 전에 거부되고 HT813로 나간 `INVITE`는 0개이며 FXO는 Idle이다. 이어 F02에 사용할 허용 번호의 설정 일치만 값 출력 없이 검사한다.
- **복구:** 실패 시 백엔드를 중지하고 허용 목록·SIP 경계를 조사한다. F02를 진행하지 않는다.

### F02. 허용 번호 실제 발신·다중 턴·상대 종료

- **추적:** VOIC-FEAT-001, PRD-02·05, SRS-T02~T06·O03.
- **Given:** F01 통과, FXO Idle, 사용자가 대상 휴대전화를 받을 준비가 됐으며 임시 백엔드의 발신 API는 loopback과 인증 토큰으로 제한됐다.
- **When:** 운영 API에서 정확히 그 번호로 **한 번만** 발신한다. 사용자가 응답한 뒤 질문 두 번을 한 통화에서 말하고 두 음성 답변을 듣고 휴대전화에서 먼저 끊는다. 통화 중 숫자 한 자리를 눌러 DTMF도 관찰한다. 서버는 SIP 상태·같은 세션 ID·RTP·DTMF 이벤트·Tempo 단계 지연을 기록한다.
- **Then:** `dialing→ringing→active→ended` 또는 실제 장비가 제공하는 동등한 상태가 구분되고, 같은 SIP 대화에서 두 번의 최종 전사·작업 결과·청취 가능한 한국어 답변이 순서대로 발생한다. 첫 답변 뒤 자동 BYE가 없고 후속 작업 요청에는 같은 통화의 승인된 문맥만 전달된다. 휴대전화 종료 뒤 SIP 종료·RTP/세션 해제·FXO Idle을 확인한다. DTMF가 없으면 통화 성공과 분리해 DTMF를 실패/미확인으로 판정한다.
- **복구:** 연결·음성·종료 중 어느 단계든 실패하거나 응답 없는 회선 점유가 15초 이상 이어지면 운영 API 취소 또는 백엔드 정상 종료로 BYE를 보내고 Idle을 확인한다. 같은 번호로 무인 재시도하지 않는다.

### D01~D03. F02 미수신의 최소 진단

- **D01 설정 확인:** HT813 `Stage Method`, `Wait for Dial-Tone`, `Dial Plan`, `Dial Plan Prefix`, `PIN for VoIP-to-PSTN Calls`의 사용 여부만 확인한다. PIN 문자열과 전화번호 전체는 기록하지 않는다. 사용자 화면과 보고로 `Stage Method=1`, `Wait for Dial-Tone=No`, DTMF 길이·간격 100 ms, 다이얼 전 지연 500 ms, 일반 숫자 발신을 허용하는 `x+` 포함 Dial Plan, 빈 Dial Plan Prefix, 빈 VoIP→PSTN PIN, PSTN access code `*00`, FXO Idle을 확인했다. 설정 자체는 D01 통과이나 PSTN 실제 발신은 D02에서 판정한다. [HT813 관리 안내](https://documentation.grandstream.com/knowledge-base/ht813-administration-guide/)와 [직접 피어링 예시](https://documentation.grandstream.com/knowledge-base/peering-ht8xx-with-ht813/)에 대조한다.
- **D02 아날로그 경로 확인:** D01을 마치고 FXO Idle과 사용자 승인을 확인한 다음, 사용자가 FXS 전화기에서 HT813의 PSTN access code(기본값 `*00`, 실제 값은 장비 설정에서 확인)를 사용해 본인 소유 시험 휴대전화로 **한 번** 발신한다. 휴대전화 벨/부재중 기록, FXS의 발신음·통화 연결 여부, 통화 종료 뒤 FXO Idle을 사용자 보고로 확인한다. 통화가 되지 않으면 PSTN 회선·접속 코드·사업자 측을 우선 조사하고 D03을 보류한다. [HT813 FAQ](https://documentation.grandstream.com/knowledge-base/ht813-faq/).
- **D03 SIP 경로 재검증:** D02가 성공하고 별도 Gate 2 승인을 받으면 P0와 같은 30분 자동 종료·SIP 메타데이터 관측·정상 BYE 복구를 먼저 준비한다. 사용자가 받을 준비가 됐을 때 허용 번호로 **한 번** 발신해 휴대전화의 실제 벨 울림과 응답, HT813 FXO 상태를 확인한다. 실제 응답이 생기면 F02의 두 턴·DTMF·상대 종료를 같은 통화에서 이어간다. 15초 이상 휴대전화에 벨이 없으면 취소·Idle 확인 후 원인 미확정으로 남긴다. D02 성공과 D03 실패의 조합은 SIP→FXO 다이얼·번호 전달 경계를 우선 조사할 근거다.

### F03. 실제 착신 DTMF·종료 시각

- **추적:** VOIC-FEAT-001, PRD-03·05, SRS-I01·I03·T03·T05·O03.
- **Given:** F02 후 FXO Idle, HT813의 종료 톤 감지는 성공한 설정 그대로이며 백엔드는 착신 준비 상태다.
- **When:** 사용자가 휴대전화로 한 번 착신해 두 번 질문·답변을 이어가고 숫자 한 자리를 누른 뒤 휴대전화에서 먼저 끊는다. 서버는 `INVITE/ACK/BYE/200`, RTP·DTMF와 단계별 span 시각을 관찰한다. 사용자는 종료 직후와 10초 후 FXO 상태를 확인한다.
- **Then:** 번호 표시 값으로 접근을 제한하지 않고 두 턴이 같은 통화에서 처리된다. 숫자·기호·지속 시간의 실제 수신 결과가 있으면 DTMF만 별도로 합격 처리한다. HT813가 BYE를 보내고 서버가 200으로 응답한 뒤 RTP·세션이 해제되며 FXO가 Idle로 돌아간다. 휴대전화 종료 버튼 시각이 신뢰할 수 있게 수집되지 않으면 종료 지연을 수치 합격으로 쓰지 않는다.
- **복구:** 종료 15초 뒤에도 회선이 In Use이거나 RTP가 열려 있으면 서버 정상 종료로 해제하고 이 단위를 실패로 기록한다.

### F04. 점유 충돌과 다음 세션 회수

- **추적:** VOIC-FEAT-001, PRD-03·06, SRS-C03·I04·T04·W01.
- **Given:** F03 후 FXO Idle. 동일한 임시 백엔드에 인증된 웹 WebSocket 시험 클라이언트와 HT813 착신이 연결된다.
- **When:** 먼저 웹 세션을 열어 점유한 동안 휴대전화에서 한 번 착신한다. 기존 웹 세션을 정상 종료한 다음 같은 회선으로 한 번 더 착신하고, 그 전화 통화 중 새 웹 세션을 시도한다. 끝나면 휴대전화에서 끊고 웹 세션을 다시 시도한다.
- **Then:** 첫 착신에는 `486 Busy Here` 또는 장비에서 관찰 가능한 통화 불가가 나타나고 그 착신에 대한 모델·작업 API 호출은 0회다. 통화 중 웹 요청은 `busy`로 거부되며 기존 통화가 지속된다. 통화 종료·회선 Idle 뒤 새 웹 세션이 수락된다. 모든 단계에서 활성 세션은 최대 하나다.
- **복구:** busy 뒤에도 세션 점유가 남으면 백엔드를 정상 종료하고 SIP/RTP·FXO 상태를 확인한다. 점유 충돌이 있는 동안 새 실전화를 반복하지 않는다.

### F05. 발신자 표시 변형 — 조건부

- **추적:** VOIC-FEAT-001, PRD-03, SRS-I01·I02.
- **Given:** F03 통과, 사용자가 별도 발신원 또는 발신번호 표시 제한을 직접 사용할 수 있고, 해당 회선의 통화 영향 범위를 승인했다.
- **When:** 다른 발신원 또는 표시 제한 착신을 한 번 수행한다.
- **Then:** Caller ID만 다르거나 없다는 이유로 거부되지 않고 동일한 SIP 피어 검증과 음성 대화가 적용된다. 실제 표시 제한을 시험하지 못하면 [가짜 SIP 증거](../../tests/integrations/ht813/logs/M006_S002_T002-TRY8.md)만 인정하고 현장 전체 Caller ID 성공으로 판정하지 않는다.
- **복구:** 회선 점유가 남으면 F03과 같은 정상 종료·Idle 확인을 수행한다.

### Q01. 반복 통화의 지연·GPU 자원·종료 톤 오검출

- **추적:** VOIC-FEAT-001, PRD-05·06, SRS-O02·O03·I03.
- **Given:** F02~F04의 필수 항목 결과가 기록됐고 Grafana/Tempo/Prometheus가 준비됐다.
- **When:** 최소 5분의 한 통화에서 질문·답변을 세 번 이상 수행하고, 다른 한 통화를 이어서 실행한다. 각 턴의 STT·작업 API·TTS span, listening→speaking, GPU 사용률·VRAM, RAM available·swap, 종료 후 FXO 상태를 수집한다.
- **Then:** 각 턴이 정상 응답하고 사용자가 끊기 전 HT813가 종료 톤으로 조기 BYE를 보내지 않는다. 각 단계 지연과 p50/p95는 실제 표본 수와 함께 보고한다. OOM·모델 재시작·회선 잔류가 없어야 한다. 요구사항에 응답시간 상한이 정해져 있지 않으므로 측정 수치만으로 속도 합격을 선언하지 않고 개선 필요성을 판정한다.
- **복구:** OOM·과도한 swap 증가·조기 BYE가 나면 반복을 중단하고 서비스를 정상 종료한다. 음성·본문은 추적에 기록하지 않는다.

### Q02. 모델 상태 저하와 복구

- **추적:** VOIC-FEAT-001, PRD-06, SRS-C05·O02, [ADR-011](../records/3_decisions/ADR-011-warm-model-services-observability.md).
- **Given:** FXO Idle, 통화 없음, 백엔드와 두 모델의 `/health=ready`가 확인됐다.
- **When:** 모델 컨테이너 하나만 계획적으로 중지하고 백엔드 `/health`의 해당 모델 상태를 읽은 다음 즉시 재기동해 `/ready` 및 백엔드 상태를 재확인한다. 다른 모델은 계속 유지한다.
- **Then:** 중지한 모델만 `degraded`로 나타나고 복구 후 두 모델이 `ready`로 돌아온다. 새 통화는 복구 전 시작하지 않는다. 이미 수행한 격리 스모크와 별도로 실제 배포 상태의 결과를 남긴다.
- **복구:** 모델 재기동 실패 시 실제 전화 시험을 중단하고 기존 Compose 상태로 복원한다.

### Q03. 보존·관측·배포 복구

- **추적:** VOIC-FEAT-001, PRD-06, SRS-O01·O02, [ADR-008](../records/3_decisions/ADR-008-local-encrypted-retention.md)·[ADR-011](../records/3_decisions/ADR-011-warm-model-services-observability.md).
- **Given:** Q01·Q02 결과가 기록됐고 기존 암호문과 키의 보존 경로가 확인됐다.
- **When:** 앞선 시험에서 생성된 암호문 파일의 개수·권한·비식별 파일명·삭제 감사 필드만 확인한다. 만료 경계는 별도 임시 파일/가짜 시계의 [기존 통합 시험](../../tests/integrations/retention/logs/M006_S002_T002-TRY1.md)을 재사용한다. Tempo trace와 Grafana 지연·GPU 패널이 실제 요청을 가리키는지 확인하고, 백엔드만 정상 종료·재기동해 `/health`와 전화 포트·보존 키 연속성을 확인한다.
- **Then:** 평문·키·전화번호가 일반 로그와 추적에 없고, 기존 암호문을 삭제하거나 다른 키로 열지 않으며, 재기동 뒤 준비 상태와 수집 대상이 복구된다. 30일 삭제 정책은 가짜 시계·격리 파일의 결정론적 증거로 판정하고 실제 운영 파일을 조기 삭제하지 않는다.
- **보류 조건:** 무인 재부팅 후 비밀 재주입 방식은 아직 정해지지 않았다. 상시 서비스·VM 재부팅 복구를 이 단위만으로 완료 처리하지 않는다.

## 이번 승인 범위에서 제외할 항목

- **FXS 외부 발신·FXO/FXS 충돌:** PRD-04, SRS-F02~F03. 전화기가 연결됐다는 최근 사용자 보고는 있으나 이번 M6 실장 시험 승인은 별도로 확보해야 한다.

- **실제 마이크 권한 UI:** 현재 별도 웹 UI가 제품 범위에서 제외돼 있다. 기존 Chrome 시험은 합성 PCM의 브라우저/WebSocket 경계만 증명한다. PRD-01의 사용자 마이크 흐름을 제품 기능으로 판정하려면 UI 범위와 시험 방법을 먼저 확정한다.
