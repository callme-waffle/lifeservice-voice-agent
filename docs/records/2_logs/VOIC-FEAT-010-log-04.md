# 1. 실행 요약

사용자가 키 주입을 알리고 “테스트 시작”을 명시했다. 실제 API 연결·종료 1회와 합성 음성 왕복 1회 통과. 이어 사용자가 착신 시험을 선택했다. 실제 전화는 아직 연결하지 않았다.

# 2. 수행 내용

## 대상 마일스톤: M15 실제 경계 시험

- 연결은 최대 15초, 음성 시험은 최대 20초로 제한한다고 사용자에게 알리고 실행했다. 자동 재시도 및 전화 발신 없음.
- 저장소의 합성 한국어 음성(3.45초)을 사용했다. 실제 개인정보 음성 및 업무 API 실행 없음. 업무 위임 시 실제 실행하지 않았음을 반환하는 시험 어댑터를 사용했으며 실제 업무 위임 인수시험으로 간주하지 않는다.
- 테스트용 암호화 저장소와 임시 키를 사용하고 종료 시 삭제했다. 실제 API 키·전사·음성 원문은 출력하지 않았다.
- 기존 GPU 호스트 SSH 접속 성공, 전화 UDP 포트 미점유 확인. 기존 STT/TTS 컨테이너 정상. 기존 Python에는 websockets/prometheus_client가 없어 검증된 이미지 실행을 준비했다.
- 이미지 전송은 자동 승인 심사가 사설 코드 원격 저장의 명시적 승인 부재로 거부했다. 전송 미실행이며 사용자에게 이미지·대상·위험을 설명하고 승인을 요청했다. 우회 없음.

## 착신 준비 재개 — 2026-11-01T23:14:19.945587+09:00

사용자가 이미지 전송 및 착신 시험을 명시 승인했다. 이미지 전송 성공. 별도 하네스 소스 전송은 자동 심사가 거부하여 실행하지 않았고, 승인된 이미지의 표준 Docker 실행 명령만 사용했다. 발신 허용목록 비우기가 착신 제한 완화라는 두 번째 거부에 대해 config.py/ bootstrap.py/ inbound.py 근거로 발신기 비활성화이고 착신 peer 제한은 유지됨을 확인·제시한 뒤 실행 허용됐다.

초기 기동은 기존 `.env`의 작업 API 재시도 값 때문에 두 번 실패했다. 원본 파일을 바꾸지 않고 이번 실행에 `VOICE_AGENT_TASK_MAX_RETRIES=0`을 적용하여 해결했다.

원격 컨테이너 `voice-live-inbound-test`, 이미지 `voice-agent-provider-check:local`, host network, HTTP loopback 18080, SIP `192.168.0.23:5061`. health `ready/openai_live/unverified`, 실제 UDP 바인딩 확인. `timeout 300s`로 수신 대기 상한, 발신기 비활성화, 키는 stdin 환경으로 전달하고 출력하지 않았다. 컨테이너 종료 시 삭제되며 암호화 보존 파일은 named volume `voice-live-inbound-test-data`에 남는다. 키는 이미지·별도 파일에 저장하지 않았다. 이 볼륨의 30일 삭제 작업은 후속 운용 시 계속 연결해야 한다.

사용자에게 수신 준비를 알리고 약 30초 대화 및 겹쳐 말하기, 종료 후 체감 결과를 요청했다. 아직 실제 전화 성공으로 판정하지 않는다.


## 실제 착신 결과 및 사용자 정정 — 2026-11-01 23:22:52 KST

사용자가 “잘 동작하는 것을 확인했습니다”라고 보고했다. 이어 “제가 대화 중 통화를 종료했습니다”라고 명확히 밝혔다. 따라서 서버 자동 종료를 사용자 통화 종료 원인으로 단정하지 않는다.

```json
{
  "calls": [
    {
      "status": "failed",
      "started_at": "2026-11-01T14:17:02.008909+00:00",
      "ended_at": "2026-11-01T14:18:28.148375+00:00"
    }
  ],
  "audio_segments": {
    "generated": 9,
    "sent": 9,
    "input": 9
  },
  "audio_seconds": {
    "generated": 80.6,
    "sent": 80.56,
    "input": 84.0599375
  },
  "transcript_artifacts": 232
}
```

통화 시작은 23:17:02 KST, 서버 종료 기록은 23:18:28 KST다. Docker 이벤트의 kill은 23:18:26, 정상 프로세스 종료(exit 0)·컨테이너 삭제는 23:18:28이었다. 실행 명령 timeout 결과는 124이고 앱은 shutdown complete를 출력했다. 조회 시 시험 컨테이너·SIP/RTP 시험 포트는 없었다. 서버 프로세스 정리는 확인됐다.

판정: 실제 Live 착신 음성 대화는 사용자 체감 및 입력/출력 암호화 기록으로 확인. 통화 종료는 사용자 직접 종료와 서버 failed 기록이 불일치하므로 정상 종료 검증을 PASS로 처리하지 않는다. 종료 버튼을 누른 정확한 시각과 당시 SIP BYE 관측이 없어 HT813 감지 문제·SIP 전달·앱 처리·시험 시간 제한 경합을 확정할 수 없다. [VOIC-BUG-011](../0_issues/VOIC-BUG-011.md)로 추적한다. 통화 시간·오디오 길이를 OpenAI 청구 사용량으로 해석하지 않는다. 이번 전화의 최종 usage/지연 지표는 컨테이너 삭제 후 확보하지 못했다.

암호화 시험 파일은 별도 named volume에 남아 있으며 상시 삭제 스케줄 연결은 미완료다. 사용자 직접 종료 검증, 상시운영, 발신, 전체 I01~I08 인수 완료와 구분한다.
