# 1. 배경 및 맥락

M6 전화 조립 공백을 해소하기 위해 [ADR-006](ADR-006-ht813-voice-turn-boundary.md)은 한 통화에 음성 요청·응답 한 번을 처리하고 응답 뒤 SIP BYE로 종료하는 방안을 정했다. 사용자는 이를 명시적으로 거부했다. 사용자가 전화를 받아 질의하고 음성 답변을 들은 뒤 같은 통화에서 계속 대화해야 하며, 정상 통화 종료는 상대 사용자가 전화기에서 통화 종료를 누를 때라고 정정했다.

HT813 RTP는 통화 동안 연속 입력이다. 기존 `VoiceOrchestrator.run()`은 한 발화의 입력 종료 뒤 STT→작업→TTS를 한 번 수행한다. 따라서 전화 통화 수명과 개별 발화 턴의 수명을 분리해야 한다. 작업 API의 기존 승인 범위는 각 **최종 전사 텍스트만** user 메시지로 전송하는 것이었다. 사용자는 후속 메시지에서 같은 통화의 이전 최종 전사·에이전트 응답도 다시 전송하는 범위를 명시적으로 승인했다.

---

# 2. 검토한 대안

## A. 한 통화에 한 요청·응답 후 자동 BYE

- 장점: 현재 코어의 단일 실행 수명과 맞고 구현이 작다.
- 단점: 사용자가 답변에 이어 질문하려면 다시 전화를 받아야 하므로 명시한 전화 대화 요구를 충족하지 못한다.

## B. 한 SIP 통화 안에서 여러 발화 턴을 반복 처리하고 상대 종료를 기다림

- 장점: 사용자가 한 통화에서 질의·응답을 계속할 수 있다. 전화 회선과 전역 단일 세션 점유를 통화 기간 전체에 묶을 수 있다.
- 단점: 발화 경계, 답변 중 입력, 이전 작업의 취소·실패, RTP 순서와 턴별 상태, 통화 종료의 동시성을 별도로 다뤄야 한다.

## C. 답변마다 SIP 통화를 다시 연결

- 장점: 기존 한 발화 코어를 반복 사용하기 쉽다.
- 단점: 실제 한 통화의 연속 대화가 아니고 벨·요금·번호 전달이 반복된다.

---

# 3. 결정 내용

**대안 B를 채택한다.** 에이전트가 허용된 번호로 한 번 발신해 상대 사용자가 받으면, 같은 SIP/RTP 통화 안에서 사용자의 발화와 에이전트 음성 응답을 여러 차례 이어 간다. 응답을 보냈다는 이유로 에이전트가 정상 통화를 끊지 않는다. 상대 사용자의 통화 종료로 들어오는 SIP BYE 또는 장비가 나타내는 동등한 종료 신호가 정상 종료 기준이다. 명시적 운영자 취소, 치명적 미디어/네트워크 장애 등 비정상 상황은 자원 회수를 위해 별도 종료 경로로 다룬다.

발화 사이의 무음을 한 턴의 입력 종료로 사용할 수 있으나, **턴 종료는 통화 종료가 아니다**. 외부 회선과 웹·전화 공통 단일 세션 점유는 발신 시도 수락부터 상대 종료 및 자원 정리까지 유지한다. 턴별 오디오/이벤트 순서와 모델 호출은 같은 통화 세션에 연결하되, 각 턴의 단계별 제한 시간·실패를 통화 전체의 자동 BYE로 곧바로 확대하지 않는다.

후속 질문의 문맥을 위해 작업 어댑터는 **현재 통화의 최종 전사와 이전 최종 전사·에이전트 응답만** `https://llm.example.test/v1/chat/completions`의 `messages`로 전송한다. 이전 통화의 내용, 부분 전사, 음성 원본은 보내지 않는다. 인증은 기존 Bearer 헤더만 사용하고 자동 재시도·응답 본문 로깅은 하지 않는다. 통화 문맥은 해당 통화 수명 동안 메모리에 보유하고 통화 종료 때 정리한다. 사용자의 별도 승인 범위는 정확히 이 데이터와 대상 API다. 실행 작업은 [M6 계획 변경안](../../../.agents/sessions/20260924-ht813-m6/PLAN-AMENDMENT-PROPOSAL.md)의 수정·재승인 대상이다.

---

# 4. 결정 사유

사용자는 전화 수신 뒤 여러 질의와 음성 답변을 한 통화에서 이어 가는 동작과 상대방의 통화 종료를 명시했다. 대안 B만 두 조건을 동시에 충족한다. 턴 경계와 통화 경계를 분리하면 STT의 유한 입력 요구를 다루면서 SIP 통화를 계속 유지할 수 있다.

---

# 5. 결과 및 영향

## A. 쉬워지는 것

- 답변 뒤 같은 전화에서 후속 질문을 받을 수 있다.
- 회선 및 세션 점유의 시작·종료 기준이 통화 수명과 일치한다.

## B. 어려워지거나 제약되는 것

- 기존 한 발화 코어를 통화 관리자가 여러 번 호출하는 조립 경계와 턴별 순서 규약이 필요하다.
- 상대방 BYE가 모델 추론·TTS 송출 중 도착해도 자원을 신속히 취소·정리해야 한다.
- 같은 통화의 이전 최종 전사·에이전트 응답 외부 전송이 승인됐으므로 작업 어댑터 계약과 민감 데이터 처리 범위를 수정해야 한다.
- 전화 실장과 여러 턴·종료·실패 복구는 Gate 1/2 범위 내에서 검증해야 한다.

---

# 6. 재검토 조건

- HT813가 상대방의 실제 종료를 SIP BYE 또는 구분 가능한 신호로 전달하지 않는 경우
- 발화 경계가 전화 소음에서 안정적으로 동작하지 않는 경우
- 모델의 문맥 길이 제약 때문에 한 통화의 승인된 대화 문맥을 유지할 수 없거나 전송 범위를 다시 바꾸어야 하는 경우
