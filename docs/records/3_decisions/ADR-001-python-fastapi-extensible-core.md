# 1. 배경 및 맥락

한국어 음성 기반 작업 에이전트는 기존 STT/TTS 모델을 로컬 GTX 1080 Ti 환경에서 연결하고, 음성 입력부터 작업 처리 및 음성 출력까지의 흐름을 제어해야 한다. 동일한 코어 기능을 웹 프론트엔드와 Asterisk 전화 채널에서 재사용하면서도 각 채널의 연결 방식은 독립적으로 확장할 수 있어야 한다.

목표는 STT/TTS 모델 자체를 개발하는 것이 아니라, 기존 모델과 외부 채널을 안정적으로 조합하고 제어할 수 있는 애플리케이션 구조를 만드는 것이다.

---


# 2. 검토한 대안

## A. 채널별 독립 애플리케이션

- 장점: 각 채널을 빠르게 개별 구현할 수 있고 초기 인터페이스 설계가 단순하다.
- 단점: STT/TTS 및 작업 처리 흐름이 웹과 Asterisk 애플리케이션에 중복되며, 모델이나 정책 변경 시 여러 구현을 함께 수정해야 한다.

## B. Python/FastAPI 메인 코어와 확장 모듈

- 장점: 공통 음성 처리 흐름을 재사용할 수 있고, FastAPI 인터페이스를 통해 프론트엔드와 Asterisk 모듈을 단계적으로 연결할 수 있다. Python 기반 음성·AI 라이브러리와도 통합하기 쉽다.
- 단점: 코어와 확장 모듈 사이의 인터페이스, 세션 수명 주기 및 스트리밍 경계를 초기에 명확히 설계해야 한다.

## C. STT, 작업 처리, TTS를 각각 독립 서비스로 분리

- 장점: 각 기능을 독립적으로 배포하고 확장하거나 교체하기 쉽다.
- 단점: 단일 로컬 GPU를 사용하는 초기 환경에서는 서비스 간 통신, 배포 및 GPU 자원 조정의 운영 복잡도가 커진다.

---


# 3. 결정 내용

Python과 FastAPI를 사용한 메인 코어 애플리케이션을 구축한다. 메인 코어는 기존 한국어 STT 모델, 에이전트 작업 처리 및 기존 한국어 TTS 모델을 잇는 공통 흐름을 제어하고 외부 연동을 위한 인터페이스를 제공한다.

프론트엔드용 엔드포인트와 Asterisk 통화·미디어 연동 기능은 코어에 연결되는 별도 확장 모듈로 구성한다. 코어가 채널별 세부사항에 직접 의존하지 않도록 하며, 이후 다른 입출력 채널도 같은 방식으로 추가할 수 있게 한다.

구체적인 STT/TTS 모델, API 세부 계약, 스트리밍 방식 및 Asterisk 연동 프로토콜은 성능 검증과 후속 계획에서 결정한다.

---


# 4. 결정 사유

FastAPI 기반 코어와 확장 모듈 구조는 사용자가 명시한 Python 애플리케이션 요구를 충족하면서, 공통 음성 처리 로직을 한곳에서 관리하고 웹 및 전화 채널을 독립적으로 확장할 수 있게 한다. 또한 모델 자체 개발을 범위에서 제외하고 기존 모델을 교체 가능한 연결 대상으로 다루는 목적과도 부합한다.

초기부터 모든 기능을 독립 서비스로 분리하는 방식보다 GTX 1080 Ti 한 대를 사용하는 로컬 배포 환경의 운영 복잡도를 낮추면서, 향후 필요할 때 경계를 분리할 여지를 남긴다.

---


# 5. 결과 및 영향

## A. 쉬워지는 것

- 웹 및 Asterisk 채널에서 동일한 STT → 작업 처리 → TTS 흐름을 재사용할 수 있다.
- 채널 모듈과 음성 모델 구현을 코어 인터페이스 뒤에서 교체하거나 추가할 수 있다.
- Python 음성 처리 및 AI 생태계와 FastAPI의 HTTP/WebSocket 기능을 활용할 수 있다.
- 코어, 모델 연결부 및 채널 연동부를 분리해 단계적으로 구현하고 검증할 수 있다.

## B. 어려워지거나 제약되는 것

- 실시간 오디오 스트리밍, 세션 상태, 취소 및 오류 전파에 대한 모듈 간 계약이 필요하다.
- 단일 GPU를 공유하는 STT/TTS 작업의 동시성 및 자원 스케줄링을 코어에서 고려해야 한다.
- Asterisk와 웹 채널의 오디오 포맷 및 지연 특성 차이를 각 어댑터에서 정규화해야 한다.
- FastAPI 프로세스와 장시간 실행되는 추론 작업의 수명 주기를 분리해서 관리해야 할 수 있다.

---


# 6. 재검토 조건

- 동시 세션 또는 지연 시간 목표를 단일 FastAPI 애플리케이션 구조로 충족하지 못하는 경우
- STT, 작업 처리 또는 TTS를 서로 다른 장비에서 독립적으로 확장해야 하는 경우
- 선택한 추론 런타임이 Python 프로세스와의 직접 통합을 지원하지 않는 경우
- FastAPI의 스트리밍 방식이 선택한 Asterisk 또는 프론트엔드 전송 방식의 요구를 충족하지 못하는 경우
