# 1. 배경 및 맥락

사용자가 env로 OpenAI Live와 온프레미스 음성 모델 기반 소통을 모두 선택하도록 요청했다. 현재 순차 STT→작업→TTS 및 전화 출력 중 입력 폐기는 Live의 연속 입출력과 맞지 않는다. GPU Compose와 기동 readiness도 모델 서비스를 항상 요구한다. Live는 기존 Realtime과 이벤트 규약이 다르다.

---

# 2. 검토한 대안

## A. Live를 STT/TTS 포트에 각각 연결

- 장점: 기존 순차 실행기 수정량이 작다.
- 단점: 동일 Live 세션의 연속 대화와 동시 입출력을 분절하여 요구를 충족하기 어렵다.

## B. 공통 대화 계약 아래 온프레미스와 Live 실행기 분리

- 장점: 기존 경로 보존과 Live의 연속 흐름을 각각 검증할 수 있다. 전화·웹의 공통 보호 정책을 재사용한다.
- 단점: 두 실행 방식과 취소·전사·보존 호환 계약을 유지해야 한다.

## C. 전체 시스템을 OpenAI 직접 SIP/WebRTC로 교체

- 장점: OpenAI 권장 WebRTC 또는 직접 전화 연결을 활용할 수 있다.
- 단점: 기존 HT813 직접 SIP/RTP·서버 보존·웹 인증을 크게 바꾸며 두 제공자 공존에 추가 설계가 필요하다.

---

# 3. 결정 내용

**대안 B를 채택한다.** 사용자가 계획·본 결정·Gate 1 승인 요청에 “승인하빈다”라고 응답하여 아래 상세 선택을 승인했다. 구현 완료를 뜻하지 않는다.

1. `VOICE_AGENT_VOICE_PROVIDER=onprem|openai_live`를 시작 시 고정하고 미지정 기본은 onprem으로 한다. 잘못된 값은 실패시키며 장애 시 자동 전환하지 않는다.
2. 온프레미스는 기존 STT/작업/TTS 턴 처리를 유지한다. Live는 공통 실행 계약 아래 별도 서버 WebSocket 어댑터로 양방향 음성을 연속 처리한다. 서버 소유 오디오·보존 경계 재사용을 위해 WebSocket을 제안하며, 공식 권장 WebRTC보다 성능이 좋다고 가정하지 않는다.
3. 기존 내부 16 kHz PCM·웹 WebSocket 및 HT813 직접 SIP/RTP를 유지한다. Live 경계에서 24 kHz로 변환한다. 입력과 출력 작업을 독립 실행하며 통화 종료 시 모두 취소·회수한다. 전역 활성 세션은 1개다.
4. 기존 작업 API를 client delegation으로 재사용한다. 위임 이벤트와 같은 세션 전사 조각·시간 정보에서 요청을 구성하고 부분성을 명시한다. 위임 ID 중복 제거와 늦은 결과 폐기를 적용한다. 원본 음성은 작업 API에 전송하지 않는다.
5. Live에서는 원본 입력 음성과 해당 대화의 작업 결과를 OpenAI로 보낸다. onprem에서는 기존 승인된 작업 API 텍스트 전송 범위를 유지한다. 다른 통화 문맥 자동 전송·보존 데이터 자동 재사용은 하지 않는다.
6. Live 기록은 10초 이하 방향별 암호화 오디오 세그먼트와 시간 범위/부분성이 있는 텍스트로 만든다. 기존 onprem 턴 기록을 계속 읽는다. 실제 송출과 생성 결과를 구별한다. 로컬 AES-GCM·접근 권한·30일 삭제·보존 실패 차단을 유지한다.
7. Live 배포는 STT/TTS/GPU 및 모델 readiness에 의존하지 않는다. onprem은 기존 모델 컨테이너·STT 준비 뒤 30초 TTS 기동 규칙을 유지한다. 제공자별 준비 상태와 원격 가용성은 구분한다. 원격 확인을 위해 health마다 과금 세션을 만들지 않는다.

# 4. 결정 사유

제공자 선택을 세션 단위 실행 경계에 두어야 Live 연속 흐름을 보존하면서 기존 온프레미스를 독립적으로 유지할 수 있다. 환경변수 선택이 배포 의존성·설정 검증·health까지 동일하게 적용돼야 한쪽 환경만 준비해도 사용할 수 있다.

---

# 5. 결과 및 영향

## A. 쉬워지는 것

동일 전화·웹 채널에서 음성 제공자를 바꿀 수 있다. Live 운용 시 음성 모델 GPU가 필수는 아니며 기존 작업 API를 유지한다. 기본 모드가 onprem이므로 새 env가 없는 기존 배포의 의도를 보존한다.

## B. 어려워지거나 제약되는 것

Live는 네트워크·API 권한·시간 기준 비용과 클라우드 음성 전송이 필요하다. 부분 전사와 실제 송출의 불일치, 에코, 시간순 기록·조회 호환을 검증해야 한다. 환경변수는 재기동 시 적용되며 통화 중 전환하지 않는다. onprem이 Live와 같은 네이티브 전이중 기능을 제공한다고 약속하지 않는다.

---

# 6. 재검토 조건

WebSocket 지연/에코/출력 제어가 계획 수용 기준을 충족하지 못하거나, 공식 API 스키마·모델 접근이 달라지거나, 완전 로컬 작업 처리·자동 폴백·통화 중 전환·다중 세션이 요구되면 재검토한다. 기존 보존/조회와 새 세그먼트 형식을 호환할 수 없으면 배포 전 재설계한다.
