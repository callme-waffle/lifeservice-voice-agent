# 1. 배경 및 맥락

[ADR-003](ADR-003-initial-task-backend-and-operating-constraints.md), PRD-06, SRS-O01은 생성 시점부터 30일간 녹취·원문을 보존하고 삭제하도록 정한다. 현재 `.env.example`에는 녹취·원문 경로와 삭제 주기·암호화 키 항목이 있지만 실제 저장·만료 삭제 구현은 없다. M6-S2의 실제 음성 시험과 M6-S3의 보존 정책 검증 전에 저장 방식과 실패 처리를 정해야 한다.

초기 배포는 단일 프로세스·단일 활성 세션이고 별도 데이터베이스는 없다. 음성·원문·번호·인증 비밀은 일반 로그에 남기지 않아야 한다. 통화 문맥은 같은 통화 안에서만 메모리에 유지하며 저장된 녹취나 원문을 후속 API 요청의 문맥으로 자동 재사용하지 않는다.

---

# 2. 검토한 대안

## A. 암호화하지 않은 로컬 파일

- 장점: 구현과 운영이 단순하다.
- 단점: 파일 시스템 접근 시 민감한 음성과 원문이 바로 노출되며, 현재 설정 양식의 암호화 키 입력과도 맞지 않는다.

## B. 런타임 키를 쓰는 로컬 암호화 파일과 주기 삭제

- 장점: 단일 프로세스·단일 호스트 배치에 맞고 별도 DB 없이 생성 시각별 보존·삭제가 가능하다. 파일명·감사 기록에서 본문과 전화번호를 제외할 수 있다.
- 단점: 키의 안전한 주입·백업·회전, 파일 손상·디스크 부족, 원자적 기록·삭제 실패에 대한 운영 절차가 필요하다.

## C. 데이터베이스의 암호화 BLOB과 만료 작업

- 장점: 항목 검색·만료 조회·트랜잭션 관리가 쉽다.
- 단점: 현재 단일 호스트 규모에는 스키마·DB 운영 및 백업 경계가 추가되고 저장소 접근 권한·암호화 계층을 여전히 설계해야 한다.

---

# 3. 결정

**대안 B를 채택한다.** 웹·전화 입력 음성과 에이전트 출력 음성을 방향·세션 ID·생성 시각별 유한 턴 아티팩트로, 최종 전사와 에이전트 응답은 텍스트 아티팩트로 보존한다. 부분 전사는 저장하지 않는다. 파일명에는 전화번호·원문을 쓰지 않는다. 16 kHz PCM16 형식과 방향 등 복호화에 필요한 메타데이터를 암호문 안에 둔다.

내용은 인증된 암호화(AES-GCM)를 적용하고, 파일마다 새 nonce를 사용한다. 30일 만료 계산용 UTC 생성 시각은 파일 헤더에 두되 인증된 부가 데이터에 포함해 내용과 결속한다. 임시 파일에 완성된 암호문을 쓰고 원자적으로 게시하며, 저장 디렉터리·파일의 접근 권한을 제한한다. 암호화 키는 런타임 환경에서만 주입하고 저장소·로그·배포 패키지에는 넣지 않는다. 필수 키나 기록 경로를 사용할 수 없으면 서비스를 준비 완료로 표시하지 않는다.

만료 기준은 각 아티팩트의 **생성 시각 + 30일**이다. 시작 시와 설정된 주기(기본 1시간)에 만료 파일을 삭제한다. 삭제 감사에는 아티팩트의 비식별 ID, 종류, 생성·삭제 시각, 결과와 실패 사유 코드만 남긴다. 본문·음성·전화번호·키는 감사와 일반 로그에 남기지 않는다. 삭제에 실패하면 다음 주기에 재시도하고 운영 오류를 표시한다. 통화 문맥은 해당 통화 종료 시 메모리에서 지운다.

사용자가 2026-09-24 M6 대화에서 “ADR-008 승인”이라고 답해 이 저장 아키텍처 결정을 수락했다.

# 4. 결정 사유

초기 운영 규모에는 로컬 파일로 충분하고 별도 저장 서비스를 추가하지 않아도 된다. 음성과 원문은 민감하므로 암호화와 접근 권한 제한을 함께 적용한다. 생성 시각을 파일별로 보존하면 통화가 길거나 중단돼도 만료 기준을 명확히 할 수 있다. 데이터 내용을 포함하지 않은 감사로 삭제 결과를 확인할 수 있다.

---

# 5. 결과 및 영향

## A. 쉬워지는 것

- 실제 녹취·원문 보존과 30일 만료를 재현 가능한 시계·파일 경계로 검증할 수 있다.
- 단일 호스트 배포에서 DB 서비스 없이 운영할 수 있다.

## B. 어려워지거나 제약되는 것

- 키가 없거나 잘못되면 기존 기록을 읽을 수 없으므로 키의 안전한 보관·복구 절차가 필수다.
- 디스크 부족·파일 손상·삭제 실패를 운영 오류로 탐지해야 한다. 원자적 기록 이전에 프로세스가 중단된 불완전 턴은 온전한 녹취 아티팩트로 남지 않을 수 있으며, 임시 파일 정리와 이 한계를 운영 문서에 기록한다.
- 키 회전·안전 삭제의 물리적 보장·멀티 호스트 공유 저장소는 이번 단일 호스트 범위에서 구현하지 않는다.

---

# 6. 재검토 조건

- 여러 호스트/프로세스의 동시 기록 또는 검색·분석 요구가 생기는 경우
- 법적·운영 요구로 보존 기간, 녹취 대상, 감사 내용, 암호화 키 관리 방식이 바뀌는 경우
- 파일 수·용량 또는 삭제 시간이 단일 호스트 운영 한도를 넘는 경우
