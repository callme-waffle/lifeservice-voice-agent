# 1. 배경 및 맥락

M1 실행을 시작하기 전에 STT와 TTS 사이의 작업 처리 백엔드, 초기 동시성, 데이터 보존 기간 및 GPU 호스트 준비 상태에 대한 운영 입력이 제공되었다. 이 값들은 Task 어댑터, 세션 제한, 저장·삭제 수명 주기 및 검증 범위를 결정한다.

인증 비밀은 사용자가 현재 세션에만 사용할 테스트 값으로 제공했으나, 저장소·문서·로그·명령 출력에는 기록하지 않는다.

---


# 2. 검토한 대안

## A. 로컬 작업 처리 모델

- 장점: 음성 데이터와 요청 처리를 완전히 로컬에서 통제할 수 있다.
- 단점: GTX 1080 Ti에서 STT/TTS와 GPU를 공유해야 하며 모델·메모리 요구가 아직 확정되지 않았다.

## B. 외부 작업 처리 API

- 장점: 음성 모델용 로컬 GPU 자원을 보존하고 Task 어댑터 경계를 통해 호출할 수 있다.
- 단점: 네트워크 가용성, 인증 비밀 관리, 원격 API 규격 및 외부 데이터 전송 정책을 고려해야 한다.

## C. 작업 처리 없이 음성 변환만 제공

- 장점: 초기 구현 범위가 작다.
- 단점: 음성 기반 작업 에이전트라는 핵심 목적을 충족하지 못한다.

---


# 3. 결정 내용

- 작업 처리 백엔드의 기본 주소로 https://llm.example.test을 사용한다.
- API 인증 비밀은 환경 변수 또는 런타임 비밀 주입으로만 전달하며 저장소와 영속 문서에 기록하지 않는다.
- 실제 API 형식, 지원 모델, 오류·시간 제한 규약은 M1 환경 조사에서 검증한다.
- 초기 동시 활성 세션 수는 웹과 전화를 합쳐 1개로 제한한다.
- 녹취 및 원문 데이터는 생성 시점부터 30일 동안 보존한 뒤 삭제한다.
- GTX 1080 Ti 호스트 실측은 별도 인스턴스 준비와 접근 정보 제공 후 수행한다.

---


# 4. 결정 사유

사용자가 작업 처리 API와 초기 운영 제약을 명시적으로 지정했다. 단일 세션 제한은 GPU 호스트가 준비되기 전 보수적인 초기 운영 범위를 제공한다. 30일 보존 정책은 영구 저장을 피하면서 제한된 기간의 운영 확인과 문제 분석을 가능하게 한다.

인증 비밀을 코드와 기록에서 분리하면 초기 테스트 키가 커밋·로그·문서에 노출되는 것을 방지할 수 있다.

---


# 5. 결과 및 영향

## A. 쉬워지는 것

- Task 어댑터의 초기 연결 대상이 명확해진다.
- 세션 스케줄러가 우선 단일 활성 세션만 처리하면 된다.
- 저장 데이터의 만료 기준과 삭제 작업의 수용 기준을 정의할 수 있다.
- GPU 호스트 준비와 독립적으로 계약·채널·API 작업을 진행할 수 있다.

## B. 어려워지거나 제약되는 것

- 네트워크 또는 원격 API 장애가 작업 처리 흐름에 영향을 준다.
- 외부 전송 데이터의 범위와 개인정보 보호를 명확히 해야 한다.
- 30일 삭제를 보장할 저장소, 스케줄러 및 감사 증거가 필요하다.
- GPU 성능 수치는 호스트 접근 전까지 검증 완료로 처리할 수 없다.

---


# 6. 재검토 조건

- 작업 처리 백엔드를 로컬 모델 또는 다른 API로 전환하는 경우
- 동시 활성 세션을 2개 이상으로 확대하는 경우
- 법적·운영 요구로 보존 기간 또는 저장 대상이 변경되는 경우
- llm.example.test의 API 규격이나 가용성이 요구사항을 충족하지 못하는 경우
