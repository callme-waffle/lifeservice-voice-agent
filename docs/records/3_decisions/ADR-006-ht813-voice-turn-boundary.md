# 1. 배경 및 맥락

M5의 `HT813Outbound.dial()`은 연결된 SIP 통화가 끝날 때까지 RTP를 수신한다. 코어 `VoiceOrchestrator.run()`의 STT 어댑터는 입력 스트림의 끝을 받아야 최종 전사를 만들고 작업 처리·TTS를 시작한다. M6-S1 bootstrap은 두 객체를 생성하지만 이 경계를 연결하지 않는다. 현재 상태로는 통화 중 양방향 음성 작업을 완료할 수 없으며, 단일 활성 세션을 발신 시도부터 BYE까지 유지하는 방식도 필요하다.

PRD-02/SRS-T03은 양방향 미디어를 요구하지만 한 통화의 대화 턴 수와 발화 종료 신호는 정하지 않았다. 이 결정은 **초기 범위를 한 통화에 한 음성 요청·한 음성 응답**으로 한정한다. 사용자는 ADR-006을 승인했으나, 별도의 M6 계획 변경안은 아직 검토 중이므로 그 구현은 계획 재승인 전 시작하지 않는다.

---

# 2. 검토한 대안

## A. 고정 길이 녹음 후 처리

- 장점: 추가 의존성과 발화 검출 로직이 적다.
- 단점: 짧은 발화도 종료 시점까지 기다리고 긴 발화는 잘릴 수 있다.

## B. 전화 키 `#`로 발화 종료

- 장점: 종료 신호가 명확하고 배경 소음의 영향을 덜 받는다.
- 단점: 음성 작업마다 전화 키 조작을 요구해 PRD의 자연스러운 음성 요청 경험을 약화한다.

## C. PCM 발화·무음 구간으로 한 턴을 자동 종료

- 장점: 사용자가 별도 키를 누르지 않아도 최종 전사에 필요한 스트림 끝을 만들 수 있다. 기존 PCM/RTP 계약을 유지한다.
- 단점: 전화선 잡음·원격 안내 음성 때문에 잘못 끊기거나 끝나지 않을 수 있으며, 임계값과 최대 발화 시간의 실장 검증이 필요하다.

---

# 3. 결정 내용

**결정:** 대안 C를 첫 실장 후보로 한다. HT813 채널과 코어 사이의 조립 경계에서 16 kHz PCM의 발화 시작·무음 지속 시간을 판단하고, 한 요청의 입력 스트림을 끝낸다. 무음 임계값·최소 발화·최대 발화 시간은 설정으로 제한하고, 오디오 원문을 일반 로그에 남기지 않는다. 한 통화에서 최종 전사→작업 처리→TTS 응답 한 번을 마치면 SIP BYE로 종료한다.

단일 세션 점유는 발신 요청을 수락하기 전부터 BYE·자원 정리까지 유지한다. 코어가 같은 점유권을 다시 획득해 충돌하지 않도록 조립/코어의 점유 인터페이스를 명시적으로 정리한다. 웹과 전화는 동일한 전역 점유 정책을 공유한다. 전화 발신 실행 경로는 별도의 새 공개 HTTP 엔드포인트를 만들지 않는 운영 명령 방식으로 정했으며, 그 명령의 번호 검증은 소켓 생성 전에 수행한다.

구체 임계값은 실장 시험 데이터가 없으므로 완료 기준으로 고정하지 않는다. M6의 [별도 계획 변경안](../../../.agents/sessions/20260924-ht813-m6/PLAN-AMENDMENT-PROPOSAL.md)에서 구현·단위 검증·승인된 경계 검증의 실행 승인을 받아야 한다. 실장 실패 시 임계값 조정 또는 다른 발화 종료 방식으로 재검토한다.

---

# 4. 결정 사유

현재 코어 계약이 끝이 있는 한 발화 입력을 요구한다. 음성으로 요청하는 사용자는 별도 DTMF 조작 없이 요청을 마칠 수 있어야 하므로 자동 발화 종료를 우선한다. 한 통화 한 요청은 현재 코어 수명 주기와 SRS의 단일 세션 정책을 가장 작은 변경으로 연결하는 범위다.

---

# 5. 결과 및 영향

## A. 쉬워지는 것

- SIP/RTP의 연속 미디어를 기존 코어의 유한 입력 스트림으로 바꿀 수 있다.
- 통화 완료와 전역 세션 점유 해제 시점을 명확히 할 수 있다.

## B. 어려워지거나 제약되는 것

- 잡음·침묵·상대방 안내음에 따른 발화 경계 오류가 생길 수 있다.
- 한 통화의 여러 요청/응답은 이 초기 범위에 포함되지 않는다.
- 코어 점유 인터페이스 변경과 전화 조립 단위/통합 검증이 필요하다.

---

# 6. 재검토 조건

- 사용자가 다중 턴 대화를 초기 요구로 확정하는 경우
- HT813 실장 음성에서 무음 판정이 안정적이지 않은 경우
- 통화 중 전역 단일 세션 점유를 현재 코어 인터페이스로 안전하게 유지할 수 없는 경우
