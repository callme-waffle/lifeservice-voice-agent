# 1. 이슈 내용

## A. 배경

2026-10-15 사용자가 프로젝트 진행현황을 확인하고 실제 서비스 시행까지 남은 작업의 처리 계획을 요청했다. 후속 답변에서 첫 개시 범위를 **전화 서비스 우선: 착신·허용 번호 발신·통화내역 조회**로 지정했다.

핵심 음성 처리와 실제 착신 대화의 성공 기록, 모델 상주·관측 스택 및 병합된 조회 API는 있으나, 실제 발신 다중 턴·반복 안정성·상시 백엔드·재부팅 시 비밀 주입·운영 복구의 완료 근거가 부족하다. 로컬 코드/세션과 공개 원격의 진행 상태도 다르다.


## B. 이슈 설명

전화 이용자가 에이전트에 전화해 대화하고, 운영자가 허용 번호로 발신하며, 종료된 통화의 내역을 확인할 수 있는 운영 가능한 서비스로 전환해야 한다. 임시 시험 성공, 코드 병합, 운영 배포, 장기 안정성 검증을 구분하고 미완료 조건을 누락 없이 추적해야 한다.

이 이슈는 기존 VOIC-FEAT-001의 전화 구현, VOIC-BUG-003의 미수신 결함, VOIC-FEAT-004/005의 조회 기능을 다시 만드는 작업이 아니다. 이들을 연결하는 **릴리스 기준·상시 운영·서비스 개시 판정**을 별도 OPS 작업으로 관리한다. 실행 순서와 설계는 파생 계획이 소유한다.

# 2. 결정 사항

## A. 결정 내용

- 최초 서비스는 전화 우선이며 동시 활성 세션 1개, 전체 FXO 착신, 정확한 허용 번호 발신, 인증된 로컬 운영 API 및 기존 30일 암호화 보존을 기준으로 한다.
- 웹 사용자 화면, FXS 독립 발신, 다중 회선/다중 사용자 서비스는 첫 개시 조건에 포함하지 않는다. 기존 요구사항에서 삭제하지 않고 후속 범위로 유지한다.
- 요청된 현황 조사·계획 수립을 수행한다. 계획 작성은 운영 배포·새 실전화 실행 승인과 구별한다.


## A-1. 실행 승인 및 관리 방식 (2026-10-16)

사용자가 계획과 통합 검증 Gate 1을 승인했다. 단계마다 독립 세션에서 구현·검증하고 본 세션은 전체 관리를 맡는다. 단계 내부 독립 작업은 서브에이전트로 병렬화하며 단계 인수와 다음 단계 진행 승인은 사용자의 MR 병합으로 확인한다. 에이전트 직접 병합은 하지 않는다. 세부 조건은 [승인 계획](../1_plans/VOIC-OPS-008-plan.md)의 D절을 따른다.

## B. 결정 사유

사용자가 확정한 전화 우선 범위에 맞춰 이미 구현된 기능을 재사용하면서 실사용을 막는 운영·검증 공백을 닫아야 한다. 기존 개별 기능 이슈에는 상시 운영과 서비스 개시를 통합 판정하는 기준이 없다.
