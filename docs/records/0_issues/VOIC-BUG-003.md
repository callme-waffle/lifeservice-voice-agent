# 1. 이슈 내용

## A. 배경

[VOIC-FEAT-001](VOIC-FEAT-001.md)의 M6-S2 실장 시험에서, 에이전트가 HT813 FXO를 통해 사용자가 제공한 본인 소유 휴대전화로 발신하는 기능을 처음 검증했다. 2026-10-09 17:33 UTC에 허용 번호 1건을 운영 API에 제출했고 API는 202를 반환했다. GPU→HT813 `INVITE`에 장비가 `100`, `180`, `200`으로 응답하고 GPU가 `ACK`를 보냈다. 서버 상태는 `active`, RTP 4000/UDP는 열렸다. 그러나 사용자는 휴대전화에 착신이 없었고 FXS 전화기도 울리지 않았다고 보고했다. 운영 API 취소 뒤 GPU `BYE`→HT813 `200`, RTP 해제, 사용자 확인 FXO `Idle`로 돌아왔다.

## B. 이슈 설명

SIP `200 OK`가 실제 PSTN 목적지의 벨 울림·응답을 입증하지 않는 상태에서 발신 세션을 `active`로 표시한다. 실제 목적지 전화는 수신하지 못했으므로 PRD-02 및 SRS-T02~T03의 외부 발신·양방향 대화 요구를 만족하지 못한다. HT813가 SIP Request-URI의 목적지 번호를 아날로그 회선으로 다이얼했는지, 한 단계 발신·다이얼 플랜·PIN·회선 사업자 조건 중 어디서 막혔는지는 아직 확인되지 않았다. 전화번호 전체, 통화 음성·원문 및 키는 이슈에 기록하지 않는다.

2026-10-11 후속 1회 재시험에서는 휴대전화 벨 울림과 통화 연결, 상대 종료 후 FXO Idle을 확인했다([TRY10](../../../tests/integrations/ht813/logs/M006_S002_T002-TRY10.md)). 최초 미수신 원인은 여전히 미확정이다. 현장 부재로 FXS 직접 발신과 음성 두 턴·DTMF는 검증하지 못했으므로 이 이슈는 열린 상태로 유지한다.

# 2. 결정 사항

## A. 결정 내용

이 건을 실제 HT813→PSTN 발신 미수신 결함으로 추적한다. 원인과 수정 방식은 미확정이다. 승인된 한 번의 발신 뒤 자동 재시도하지 않고 후속 실전화는 현 설정과 원인 조사 후 별도로 진행한다.

## B. 결정 사유

SIP 연결 성공과 외부 휴대전화 착신은 서로 다른 경계이며, 현장 실패를 가짜 SIP 성공이나 내부 상태 `active`로 덮어 완료 처리할 수 없다.
