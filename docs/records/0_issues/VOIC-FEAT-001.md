# 1. 이슈 내용

## A. 배경

한국어 음성으로 작업을 요청하고 결과를 음성으로 제공할 수 있는 로컬 음성 기반 작업 에이전트가 필요하다. 기존 한국어 STT/TTS 모델을 현재 보유한 NVIDIA GeForce GTX 1080 Ti에서 실행하고, Python 애플리케이션이 전체 음성 처리 흐름을 제어할 수 있어야 한다. 이 작업의 목적은 STT/TTS 모델 자체를 새로 개발하거나 학습하는 것이 아니다.

동일한 에이전트 기능을 웹 기반 인터페이스뿐 아니라, 전화선이 연결된 기존 Asterisk 장비에서도 사용할 수 있어야 한다. 이를 위해 FastAPI 기반 메인 코어가 음성 처리 흐름과 공통 기능을 제공하고, 프론트엔드 엔드포인트 모듈이나 Asterisk 연동 모듈을 필요에 따라 추가할 수 있는 확장형 구조가 필요하다.

## B. 이슈 설명

다음 기능과 제약을 충족하는 음성 기반 작업 에이전트 시스템을 정의하고 구축해야 한다.

- 새 모델을 개발하는 대신 한국어를 지원하는 기존 STT/TTS 모델을 선정하여 연결한다.
- STT 입력, 에이전트 작업 처리, TTS 출력으로 이어지는 흐름을 Python 애플리케이션에서 제어한다.
- 메인 코어는 FastAPI를 사용해 구현하고, 외부 모듈이 연결할 수 있는 명확한 인터페이스를 제공한다.
- STT/TTS 추론은 GTX 1080 Ti를 보유한 로컬 환경에서 실행 가능해야 한다.
- 프론트엔드용 엔드포인트를 독립 모듈로 추가하여 웹 기반 에이전트를 연결할 수 있어야 한다.
- Asterisk 통화 제어와 양방향 음성 미디어 전달을 담당하는 연동 모듈을 코어에 추가할 수 있어야 한다.
- 채널별 기능이 코어의 음성 처리 및 작업 처리 로직을 중복 구현하지 않도록 확장 가능한 모듈 구조를 제공한다.

사용할 기존 모델과 통신 기술을 선택하기 전에 GTX 1080 Ti의 메모리 및 연산 제약, 한국어 인식·합성 품질, 응답 지연, 스트리밍 지원 여부, 라이선스, 오프라인 운용 가능성, Asterisk 호환성을 비교 검증해야 한다.

현재 다음 사항은 미확정이며 후속 계획에서 요구사항 확인 및 기술 검증이 필요하다.

- llm.example.test이 제공하는 작업 처리 API의 세부 규격과 사용할 모델
- 목표 응답 지연, 목표 STT 정확도 및 TTS 자연스러움
- 웹 클라이언트의 실시간 음성 전송 방식과 API 인증·권한 요구사항
- Asterisk 버전 및 사용 가능한 연동 인터페이스(예: ARI, AMI, AGI, AudioSocket, SIP/RTP)
- 전화 통화의 발신·수신·전환·종료 등 필요한 제어 범위
- 30일 보존 대상 데이터의 저장 형식, 암호화 및 삭제 감사 방식

## C. 2026-09-24 전화 환경 및 단계별 요구 정정

초기 대화에서 Asterisk 장비라고 부른 `192.0.2.17`은 실제로 Grandstream HT813이다. 현재 Asterisk 서버는 설치되어 있지 않다. HT813의 FXO 포트에는 외부 전화선이 연결되어 있고 FXS 포트에는 아직 전화기가 연결되지 않았다.

전화 기능의 우선 범위는 다음과 같다.

- 에이전트가 HT813의 FXO와 연결된 외부 회선을 사용해 발신한다.
- 외부 회선으로 들어오는 통화는 향후 FXS에 연결할 전화기로 모두 전달한다. 에이전트는 이 착신을 받지 않는다.
- FXS 전화기에서 거는 통화는 가능하다면 모두 외부 회선으로 발신한다.
- `FXS → 에이전트`와 `외부 → 에이전트` 흐름은 후속 단계로 미룬다.

사용자는 Asterisk 서버를 추가할 수 있으나, 위 범위를 HT813 직접 SIP/RTP 연동으로 달성할 수 있다면 이를 선호한다. 구체 기술 선택과 기존 승인 계획의 변경은 별도 아키텍처·계획 검토 대상이다.

## D. 2026-09-24 에이전트 발신 통화 수명 정정

에이전트가 FXO 외부 회선으로 발신해 사용자가 전화를 받으면, 사용자는 **같은 통화에서 여러 번 질의하고 음성 답변을 들으며 대화를 계속**할 수 있어야 한다. 한 요청·한 응답 뒤 에이전트가 자동으로 전화를 끊는 동작은 사용자가 명시적으로 거부했다. 정상 통화는 상대 사용자가 전화기에서 통화 종료를 누를 때 끝난다. 발화 한 번의 종료와 통화 종료는 서로 다른 사건이다. 장애·운영자 취소 시 안전한 회선 회수는 별도로 필요하다.

이 정정은 기존 이슈의 에이전트 외부 발신 기능을 구체화한다. 별도의 신규 이슈로 분리하지 않는다. 사용자는 후속 메시지에서 **같은 통화의 이전 최종 전사와 에이전트 응답**을 현재 전사와 함께 지정된 작업 API에 전송하는 범위를 승인했다. 다른 통화의 문맥·부분 전사·음성 원본의 외부 전송은 포함하지 않는다. M6 구현 계획 변경은 별도 승인 대상이다.


## E. 2026-09-24 M6 외부 착신 범위 재정의

사용자는 M6에서 HT813 FXO에 연결된 외부 회선으로 들어오는 **모든 통화가 에이전트에 접근**하도록 명시했다. 발신자 Caller ID를 허용 목록으로 제한하지 않는다. 처음 문의한 “허용 Caller ID는 에이전트, 그 밖은 FXS” 분기는 철회됐다. 앞서 정한 외부 착신→FXS 로컬 전달 요구는 이번 M6의 착신 목적지에서 대체한다. FXS 전화기가 미연결이므로 해당 실장 검증은 계속 수행하지 않는다.

이 변경은 **착신 접근 정책**이다. 에이전트가 외부로 거는 전화의 정확한 허용 번호 정책은 유지한다. 같은 통화의 다중 턴·상대 종료와 작업 API 전송 범위는 ADR-007의 기존 사용자 승인 조건을 따른다. HT813의 실제 착신 SIP/RTP 전달과 Caller ID·회선 점유는 아직 검증되지 않았다. 신규 착신 시나리오의 M6 계획 변경·ADR-009·Gate 1은 2026-09-24 승인됐다. Gate 2는 실행 직전 별도로 처리한다. 기존 이슈의 후속 전화 범위를 M6로 당겨 온 것이므로 새 이슈를 만들지 않는다.

## F. 2026-10-07 모델 상주와 관측성 요구

실착신 세 턴에서 응답은 들렸지만 speaking→다음 listening 간격이 42.2/24.2/40.6초였다. STT·TTS 모델을 턴마다 로드하는 구조와 전체 TTS 합성·송출이 지연 원인 후보다. 사용자는 모델별 독립 컨테이너, STT 준비 완료 후 TTS 30초 지연 기동, 백엔드의 모델 준비 상태 확인, STT/작업 API/TTS Tempo 추적과 Grafana 지연·GPU 사용량 가시화를 명시 요청했다. 모델 개발이나 기존 통화 접근 정책 변경은 포함하지 않는다. M6 성능·배포 범위에서 수행하며 [ADR-011](../3_decisions/ADR-011-warm-model-services-observability.md)에 배치 결정을 기록한다.

# 2. 결정 사항

## A. 결정 내용

- 이 작업은 신규 기능 이슈(FEAT)로 관리한다.
- 모델 개발·학습은 범위에서 제외하고, 기존 한국어 STT/TTS 모델의 선정과 연동을 범위로 둔다.
- Python과 FastAPI로 메인 코어를 구현하여 음성 처리 흐름을 제어하고 공통 인터페이스를 제공한다.
- 프론트엔드 엔드포인트 및 Asterisk 연동은 코어에 연결되는 확장 모듈로 구성한다.
- 구체적인 STT/TTS 모델, API 세부 계약 및 Asterisk 통신 방식은 후속 계획과 검증을 통해 결정한다.
- 작업 처리 백엔드는 https://llm.example.test을 사용하며 인증 비밀은 저장소 외부에서 주입한다.
- 초기 동시 세션 수는 1개로 제한한다.
- 녹취 및 원문 데이터는 30일간 보존한 뒤 삭제한다.
- GTX 1080 Ti 호스트 접근 정보는 별도 인스턴스 준비 후 제공받는다.
- 전화 기능의 기존 발신 결정은 [ADR-004](../3_decisions/ADR-004-ht813-direct-outbound-telephony.md)를 따른다. 외부 착신 목적지는 위 E절의 사용자 정정이 C절보다 최신이며, M6에서 전체 착신→에이전트로 바뀐다. 기술 방식과 승인 계획의 M6 변경은 ADR-009와 VOIC-FEAT-001-plan-02에 승인·반영됐다.
- 에이전트 FXO 발신 통화는 [ADR-007](../3_decisions/ADR-007-ht813-multiturn-call-lifecycle.md)의 다중 턴·상대 사용자 종료 기준을 따른다. 한 응답 뒤 자동 BYE로 끝내는 ADR-006은 사용자 정정으로 대체됐다.

## B. 결정 사유

사용자가 요구한 결과는 기존 결함 수정이나 모델 개발이 아니라, 기존 음성 모델을 조합해 여러 접근 채널에서 재사용할 수 있는 새로운 음성 에이전트 기능이다. 공통 흐름을 FastAPI 코어에 두고 채널 연동을 모듈화하면 웹과 전화 연동을 단계적으로 추가하면서 핵심 로직의 중복과 결합도를 줄일 수 있다.
